# Session 2026-09-19: fewer frames to OCR, and the first human review round

A summary of the working session: what was asked, what was decided, and what
came out of it. Written 2026-09-20 from the session's own messages and results.
It is a summary, not a transcript.

Branch: `feat/scroll-coverage-selection` (local only, never pushed; `main`
stayed at `364790d`). All frame results below were produced **without any
OpenRouter call**.

---

## 1. The problem we started from

The pipeline was sending a median of **27 frames per video** to the OCR model,
while typically only about **3 frames actually carry the numbers**. The request
was, in order:

1. read the whole project and report on it;
2. re-run `test-frame/` through the **local** pipeline only (classify + dedup,
   no OCR calls), mirroring `test-frame/`'s folder structure in the output;
3. investigate *why* so many frames get through, and propose options **without
   implementing anything**;
4. then implement the recommendations in order, stopping to say exactly what
   human work was needed at each point.

The investigation found the cause was not the classifier alone. Perceptual-hash
dedup compares whole frames, so two screens differing only in a small row of
digits look identical, while two frames of the same screen at different scroll
positions look different. It both **lost metrics** and **kept redundant
frames**.

### The four recommendations

| # | Recommendation | Status |
|---|---|---|
| 1 | Scroll-aware dedup: reconstruct the scroll and keep the fewest frames covering each page | done |
| 2 | Narrow the `good` label to "a schema metric is readable", then retrain | done |
| 3 | Metric-coverage selection: read each frame locally, keep the fewest covering every metric | done |
| 4 | Stillness/holds as a tie-breaker only, never as a selector | done |

## 2. Decisions made along the way

- **Local OCR dependency: Tesseract** (`fas+eng`), chosen over the
  alternatives, installed in the Dockerfile. If the binary is missing the
  coverage step is skipped and logged, never fatal.
- **Ground truth and relabelling were done by me, not the user.** The user
  explicitly handed both tasks back ("do Task A and Task B yourself, instead of
  waiting on me"), on the basis of visual inspection of the frames. This is
  worth remembering: **the ground truth is my own labelling**, not an
  independent source.
- **`scroll` became the default** only after it was measured against that
  ground truth and lost no metrics.
- **Docker: verify only.** No long-running containers; every check ran as a
  one-off `--rm --no-deps` container with the repo bind-mounted read-only.
- **Commits: a new local branch, no push.** Staging stayed explicit
  (`git add <path>`, never `-A`), with a size and secret check before each
  commit.
- **Nothing was to be overwritten.** After the mistake in §5, the user's
  standing instruction became: don't overwrite or lose any existing results,
  logs, backups or previous test outputs, don't skip anything silently, and
  stop and ask if unsure whether an action is reversible.

---

## 3. What was built

- **`processing/frame_selection.py`** — scroll-aware selection: whole-frame
  block alignment, pinned-band detection, page reconstruction, coverage with
  row-height overlap, content verification row by row, stillness as tie-break.
- **`processing/metric_coverage.py`** — local Tesseract read of each frame, then
  a set cover over the metrics found, with an "unrecognised" and a value
  backstop as safety nets.
- **`processing/selection_pipeline.py`** — `choose_ocr_frames(...)`, the single
  function that production **and every tool** call, so their results cannot
  diverge.
- **Schema additions** — `gender_men` / `gender_women`, and the Top sources of
  views fields `source_feed | reels_tab | profile | explore | stories | search |
  other`, in the prompt, the Excel export and the coverage step.
- **Tooling** — `training/eval_selection.py` (frames sent and metrics lost per
  strategy), `training/eval_feedback.py` (replays human feedback as regression
  checks), `training/review_videos.py` (builds a review round),
  `training/trace_frames.py` (updated to the production stages).
- **Tests** — `tests/test_frame_selection.py` and `tests/test_metric_coverage.py`,
  whose fixtures are the *exact* Tesseract output from the reviewed frames;
  145 tests pass.

## 6. Review round 01: the human feedback loop

The user placed six new videos (none in the training data) and asked for an
ongoing loop: run them locally, lay out the final selected frames for review,
take feedback, fix the causes. Round 01 sent **39 frames** across the six.

### The feedback, and what each item turned out to be

| video | verdict | cause found | after the fixes |
|---|---|---|---|
| `5361dd11` 189, `1f2bdcac` 183, `4985b8cc` 276 | rates only, not needed | kept by the "no metric recognised, but there's a number" rule, which counted *any* 2-digit number — rate percentages, chart axis ticks, status-bar noise | not sent |
| `5361dd11` 237 | **should have been sent** | **Top sources of views was not in the schema at all**, and the earlier relabel had taught the classifier those screens were bad (it scored 0.007) | sent (as 234, the same screen) |
| `8102e03d` 585/603, 471/480 | duplicates, keep one | OCR misread "Likes 124" as "'3 124", so two identical frames both looked necessary | one of each pair |
| `bf96a4ca` 033, 054 | captured before the numbers loaded | 033: status-bar noise counted as numbers. 054: on a tie the *earliest* frame won, which was still loading | not sent |
| `bf96a4ca` 060 | had loaded numbers but was dropped — find out where | it passed the classifier (0.79) and scroll selection, then coverage dropped it as "already covered" by 033/054. The real fault was keeping those two | its numbers arrive via 087; ties now go to the most complete frame |
| `edc93edd` | good, no changes | — | everything marked needed is still sent |

### Three further bugs the tests then exposed

- OCR adds a leading digit to a percentage next to a bar graphic
  ("96.5%" read as "896.5").
- The value backstop kept a new frame for every small-percentage misread; it now
  guards counts only.
- A section header ("Interactions ⓘ") at the screen edge took the donut's arc,
  read as digits, as its value — which briefly lost the real Interactions value
  on another video.

## 7. The model

Two training rounds were deployed, each at threshold 0.30, each with a backup
and an exact undo (`training/relabel/<round>/apply.py --restore`):

1. **`2026-09-19-relabel`** — `good` narrowed to "a schema metric is readable".
2. **`2026-09-19b-sources`** — 131 Top-sources frames moved bad → good (all
   checked by eye; one excluded as mid-transition), plus the round-01 verdicts
   as training labels. Held-out recall is 1.000 up to 0.85.
