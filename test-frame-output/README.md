# Frame review — deployed classifier + 16/16 dedup

> **v1 — superseded.** This is the 2026-09-14 pipeline (model
> `2026-09-14-nodedup` at 0.95, phash dedup). It is kept as the baseline for
> `../test-frame-output-v3/`. The generator below is left unchanged on purpose:
> it is the recipe for these results, but since config.py has moved on it no
> longer reproduces them. Use v3's generator for the current pipeline.

Local pre-OCR pipeline only (extract → classify → dedup → batch). **No OpenRouter
call was made.** Generated by `_generate_review.py` using the app's own modules and
the effective settings in `processing/config.py`. The script refuses to run if
anything overrides those settings: threshold 0.95, phash 16/16, every 3rd frame,
720p, batch 12. Model: `2026-09-14-nodedup`.

One folder per video, mirroring `test-frame/`:

| | |
|---|---|
| `review.html` | open this first — timeline, frames sent (per request), dedup groups, rejected frames |
| `frames.csv` | one row per extracted frame: score, label, dedup role, group, hash distance, batch |
| `groups.json` | each dedup group: representative (sent) + frames merged into it |
| `kept/` | frames that would be sent onward, named `b<request>_<position>__<frame>` |
| `groups/` | `g<id>__<rep>__x<size>/` — `REP__…` is sent, `dNN__…` merged at Hamming distance NN |
| `rejected/` | classifier rejects, named `<score>__<frame>` |
| `frames/` | every extracted frame |
| `summary.json` | settings, model md5, counts, whether the video was in the training set |

The dedup grouping is checked against `processing/dedup.dedupe_frames()`: the
kept set is identical, and the script aborts if it isn't. A merged frame is
assigned to the first kept frame within distance. `reps_within_distance` lists
every kept frame it matched.

Regenerate: `.venv-train/bin/python test-frame-output/_generate_review.py --force`
